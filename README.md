
# DealCloser AI

ผู้ช่วยเซลล์ AI สำหรับร้านค้าออนไลน์ SME ที่ตอบแชต แนะนำสินค้า ตรวจจับความลังเลของลูกค้า โน้มน้าวใจ และนำไปสู่การปิดการขายพร้อมชำระเงินจบในแชต LINE OA ได้ตลอด 24 ชั่วโมง

นี่คือแนวคิดและต้นแบบสำหรับ AI for All Thailand Innovation Sprint (Pillar: SMEs) ยังไม่ใช่ระบบที่ผ่านการทดสอบกับร้านค้าจริง ตัวอย่างบทสนทนาและตัวเลขในเดโมเป็นข้อมูลจำลองเพื่อให้เห็นวิธีทำงานเท่านั้น

---

## ปัญหาที่เราอยากแก้

ร้านค้า SME ที่ขายสินค้าผ่าน Social Media ต้องตอบแชตลูกค้าให้เร็วเพื่อไม่ให้เสียโอกาสขาย แต่ช่วงกลางคืนหรือเทศกาลมักไม่มีคนตอบ แชตบอตทั่วไปก็ตอบได้แค่คำถามซ้ำๆ ไม่สามารถแนะนำสินค้า ต่อรองราคา หรือปิดการขายแทนคนได้

จากข้อมูลที่ทีมรวบรวม (แหล่งอ้างอิงด้านล่าง):

- ยอดทักแชตหลัง 18.00 น. ถึงเที่ยงคืน อาจสูงถึง 40-50% ของทั้งวัน
- หากร้านค้าตอบช้าเกิน 5-10 นาที อัตราที่ลูกค้าทิ้งแชตไปซื้อร้านอื่นอาจสูงกว่า 60-70%
- คนไทยนิยมถามสต็อก ขอดูรูปจริง และต่อรองโปรโมชันผ่านแชตก่อนโอนเงิน มากกว่ากดตะกร้าสินค้าเอง

โจทย์นี้มาจากประสบการณ์ส่วนตัวของสมาชิกในทีมและการสังเกตพฤติกรรมผู้ซื้อ-ผู้ขายออนไลน์ เรายังไม่ได้สัมภาษณ์ผู้ประกอบการเป็นระบบ และตัวเลขข้างต้นเป็นค่าประมาณจากแหล่งข้อมูลทั่วไป ไม่ใช่ผลสำรวจที่ทีมทำเอง

## แนวคิดของเรา

DealCloser AI ให้ร้านค้าใส่ข้อมูลแคตตาล็อกสินค้า สต็อก และกฎโปรโมชัน จากนั้นระบบจะ:

- **ตอบแชตและแนะนำสินค้า** -- เข้าใจข้อความภาษาไทย สแลง คำย่อ แล้วดึงข้อมูลจากแคตตาล็อกจริงมาตอบ พร้อมส่งการ์ดสินค้า (Flex Message) ให้ลูกค้ากดเลือก
- **ตรวจจับความลังเล** -- หากลูกค้าเงียบไปเกิน 2 นาที หรือพิมพ์ประโยคลังเลเช่น "ขอคิดดูก่อน" "ลดได้อีกมั้ย" ระบบจะจับสัญญาณได้
- **โน้มน้าวใจอัตโนมัติ** -- เสนอดีลจำกัดเวลา ของแถม หรือ Cross-sell ภายในขอบเขตที่ร้านค้าตั้งไว้
- **ปิดการขายจบในแชต** -- สรุปออเดอร์ สร้าง QR พร้อมเพย์ ตรวจสลิป ขอที่อยู่จัดส่ง และตัดสต็อก โดยไม่ต้องออกจากแชต
- **ส่งต่อให้คนจริง** -- หากคำถามนอกเงื่อนไขหรือลูกค้าไม่พอใจ ระบบจะแจ้งเตือนและสลับให้แอดมินเข้ามาตอบทันที

ระบบช่วยคำนวณและแนะนำ แต่เจ้าของร้านยังเป็นผู้กำหนดขอบเขตส่วนลด เงื่อนไขโปรโมชัน และตัดสินใจขั้นสุดท้ายผ่านแดชบอร์ด

## วิธีทำงานและเทคโนโลยี

เราเลือกไม่ให้ AI แต่งข้อมูลสินค้าหรือสัญญาเกินจริง แต่ให้อ้างอิงเฉพาะฐานข้อมูลที่ร้านค้าใส่ไว้ ควบคุมด้วย Guardrails และ State Machine

| ชั้น | เทคโนโลยี |
|---|---|
| Channel | LINE Messaging API, Webhook, Flex Message |
| Backend | Node.js / Python (FastAPI), State Machine, Order Engine |
| AI Engine | Gemini 1.5 Flash / GPT-4o-mini, RAG, Guardrails |
| Data | Product Catalog, Stock (Realtime), Promo Rules, Chat History |

สูตรการทำงานหลัก:

1. ลูกค้าทักแชต > ระบบรับข้อความผ่าน Webhook
2. AI Engine วิเคราะห์เจตนา > ดึงข้อมูลสินค้าผ่าน RAG > ตอบกลับพร้อม Flex Message
3. หากลูกค้าลังเล > Hesitation Detection ทำงาน > ส่ง Nudge ภายในขอบเขตที่ร้านค้าตั้งไว้
4. หากลูกค้าตกลง > สรุปออเดอร์ > สร้าง QR ชำระเงิน > ตรวจสลิป > ตัดสต็อก
5. หากเกินขอบเขต > แจ้งเตือนแอดมินให้เข้ามาตอบแทน (Human Takeover)

State Machine ล็อกทุกขั้นตอนไม่ให้ AI ให้ส่วนลดเกินงบ ยืนยันสินค้าที่หมดสต็อก หรือข้ามขั้นตอนการชำระเงิน

## ตัวอย่างจำลอง

บทสนทนาต่อไปนี้เป็นตัวอย่างที่ทีมจำลองขึ้นเพื่อให้เห็นวิธีทำงาน ไม่ใช่บทสนทนาจริงกับลูกค้า:

```
ลูกค้า: "มีกระเป๋าสีดำมั้ยคะ"

AI: ส่งภาพกระเป๋าสีดำจากสต็อก + Flex Card [ดูรีวิว] [สั่งซื้อทันที]

ลูกค้า: "ขอคิดดูก่อนนะคะ..."

[ระบบตรวจจับความลังเล]

AI Nudge: "รุ่นนี้เหลือ 2 ใบสุดท้าย คอนเฟิร์มคืนนี้แถมผ้าผูกหู 150 บาทฟรี"

ลูกค้า: "เอาค่ะ"

AI: สรุปออเดอร์ > QR ชำระเงิน > ตรวจสลิป > ขอที่อยู่ > ตัดสต็อก > สำเร็จ
```

## ทำไมจึงออกแบบแบบนี้

1. **ไม่ให้ AI สัญญาเกินจริง:** ล็อกขอบเขตส่วนลดและสต็อกด้วย State Machine + Guardrails ทุกคำตอบอ้างอิงจากฐานข้อมูลที่ร้านค้าใส่เท่านั้น
2. **เจ้าของร้านคุมการตัดสินใจ:** ระบบช่วยคำนวณและแนะนำ แต่เจ้าของเป็นผู้กำหนดกฎโปรโมชัน ขอบเขตส่วนลด และสามารถเข้าแทรกแซงแชตได้ทุกเมื่อ
3. **ส่งต่อให้คนจริงเมื่อจำเป็น:** ไม่ฝืนให้ AI ตอบทุกกรณี หากเกินขอบเขตหรือลูกค้าไม่พอใจ ระบบส่งต่อให้แอดมินทันที
4. **เปิดสูตรให้ตรวจสอบได้:** ทุกคำแนะนำอธิบายได้ว่ามาจากข้อมูลอะไร ไม่ซ่อนที่มา
5. **เริ่มต้นง่าย:** ร้านค้าใส่แคตตาล็อกสินค้าและกฎโปรโมชัน ไม่ต้องสร้าง Flowchart หรือเขียนสคริปต์ซับซ้อน

## สิ่งที่ยังไม่พิสูจน์

- เรายังไม่ได้ยืนยันว่าร้านค้ากลุ่มเป้าหมายพบปัญหาตอบแชตช้าจนเสียยอดขายบ่อยแค่ไหน หรือเสียรายได้เท่าไร
- ยังไม่มีผลว่าการใช้ AI ปิดการขายแทนคนช่วยเพิ่ม Conversion Rate ได้จริง
- ยังไม่ได้ทดสอบว่าลูกค้าจริงจะรู้สึกสะดวกหรือรำคาญกับการที่ AI โน้มน้าวใจ
- ยังไม่ได้ยืนยันว่า Guardrails และ State Machine ป้องกัน Hallucination ได้ครอบคลุมทุกกรณี
- ตัวเลขตลาด (SME 3.2 ล้านราย, Social Commerce 30-40%) อ้างอิงจากแหล่งข้อมูลทั่วไป ไม่ใช่การสำรวจของทีม

เราระบุสิ่งเหล่านี้ไว้เพื่อความโปร่งใส ไม่ใช่เพื่อลดคุณค่าของแนวคิด

## เป้าหมายที่ตั้งไว้สำหรับ MVP (ยังไม่ได้วัดจริง)

| ตัวชี้วัด | เป้าหมาย |
|---|---|
| Conversion Rate | เพิ่มขึ้น >= 15-20% เทียบกับแอดมินคน/บอตเดิม |
| Response Time | <= 5 วินาที (ข้อความแรก) |
| After-hours Revenue Share | >= 25-30% ของยอดขายรวม |
| Cart Recovery Rate | >= 10% |

ตัวเลขเหล่านี้เป็นเป้าหมายที่ตั้งไว้ ยังไม่ได้วัดจริงกับร้านค้า
